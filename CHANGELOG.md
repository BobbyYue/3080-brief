All notable changes to this project are documented here. The project follows [Semantic Versioning](https://semver.org/).

## [0.16.0] - 2026-10-25

- Bind checked delivery to the actual evidence files and current caller context. Reject changed evidence, conflicting references, stale tasks and output-option abbreviations that could bypass a blocked delivery.
- Add `scripts/host_delivery.py` for applications to validate and consume the exact checked output. This supplies an integration point; it does not install an interceptor or deploy any application.
- Separate writing instructions from final-reader content in the existing contextual review, including paraphrased instruction echoes. Preserve useful methodology, disclosures, genuine recipient instructions and quoted material.
- Add `scripts/evaluate_judgments.py` and a synthetic format example for frozen reviewer-calibration results, with missing/error/abstention accounting. No real human benchmark or semantic-quality certification is claimed.
- Synchronize installed configuration revision 38. Keep the existing report examples and their historical provenance unchanged; this release adds no reviewer or review round.

## [0.15.0] - 2026-10-23

- Require direct-expression planning, text-bound unit comparisons and a final whole-document check in the existing Reader review. Compare corrective or cautionary wording with equally accurate direct alternatives, while preserving necessary prohibitions, refusals, negative findings and uncertainty.
- Check cumulative effort across titles, the takeaway, visual labels, the question table and body. Pattern counts select inspection candidates; they are not word bans or automatic rewrite thresholds. Useful repetition across the three TLDR units remains valid.
- Use the actual candidate's reading surface once, including its existing bound rendered-text snapshot where needed. Supporting excerpts and visual-specification metadata do not create artificial duplicate occurrences or another rendering pass.
- Reject missing, stale and unresolved comparison evidence in full, scoped and explicit Fast delivery. Treat an adequately recorded request for revision as a content failure, not a transport error; preserve the three-round labeled-draft exit.
- Upgrade: add `expression_plan` to the locked required-answer plan, `expression_review` to complete-unit records and version 5 `reader_value` evidence to existing reviews. Regenerate affected records without silently resetting ongoing runs or backfilling PASS. See [direct expression](skills/3080-brief/references/direct-expression.md).
- Internal configuration advances from 35 to 36. The entrypoint remains 92 lines, with no additional reviewer or review round. The offline suite contains 382 unit tests, including synthetic keep/fix, meaning-preservation and workflow regressions; it does not establish measured reader preference or guaranteed writing quality.
- Retain the existing Claude Code example and its v0.14.0 generation provenance. This release updates the Skill and documentation, not the article's reviewed HTML.

## [0.14.0] - 2026-10-23

- Require a source-grounded body plan before prose. Map planned reader questions to visible explanations and check them during rendering, review readiness and checked delivery. Empty bodies, heading-only bodies, overview-only answers, stale plans and hidden-only explanations no longer pass as complete articles.
- Keep full explanatory bodies as the default. Summary-only output requires an explicit user request and reviewed exclusions; thin sources may still have concise bodies. There is no minimum word or section count, extra reviewer or extra review round.
- Add managed task identity, original review-return capture, bounded recovery and checked full, scoped, Fast and three-round draft exits. Preserve independent review evidence and bind the final output to the bytes actually checked; Fast remains a disclosed self-check.
- Add contextual content-value and source-attribution checks to existing reviews. Reuse unchanged measurements, compact repeated transport context and release dependent review work when its input is ready. These changes do not establish measured speedups or human comprehension.
- Publish the complete English Claude Code example with six explanatory body sections; both README editions link to the same online article. Its example-specific rendering repairs remain separate from the installable package.
- Pin CI to Ubuntu 24.04 so the existing Python 3.9, 3.11 and 3.12 matrix can run. All public test fixtures are synthetic; task-local review records and source material are excluded.
- Upgrade: initialize a managed lifecycle before writing; lock the body plan against the request, sources and claim ledger; supply the current brief and visible-body evidence where required. Old review bundles cannot be retroactively labeled as managed acceptance. See [managed execution](skills/3080-brief/references/writing-execution.md) and [body completeness](skills/3080-brief/references/reading-layout-contract.md).
- Internal configuration advances from 29 to 35; repository version is 0.14.0. Enforcement applies to the cooperating workflow, not every host action. A working review backend is required for independent acceptance; no new host-wide integration or semantic-quality guarantee is claimed.

## [0.13.0] - 2026-10-10

- Strengthen source-shaped openings, natural syntax, necessary caveats and distinct jobs for the judgment, picture and table. Keep every P0 claim and the existing weighted coverage requirement.
- Add a checked-delivery CLI for standard and scoped review paths. Bind the actual local delivery file during readiness and review, then return its exact checked bytes rather than a regenerated copy.
- Require scoped final files to belong to reviewed content/render layers; detect visible-content changes even when labeled layout-only. Retain and revalidate original reused review records without restarting valid full audits.
- Bind delivery to the digest actually consumed by verification, closing the reproduced A-to-B-to-A file-change race. Add missing/stale-review, detached-file, exact-output and valid-reuse regressions.
- Upgrade: include `--delivery-artifact` in readiness, review packets and before/after scope snapshots; include the same file in an appropriate layer. Regenerate affected plans. Internal configuration advances to 29; repository version is 0.13.0.
- Fast, repair-exhausted drafts and live/native publishing retain their existing policies and are not newly enforced by this wrapper. No extra reviewer or retry round is added. Offline tests do not certify model judgments or host integration.

## [0.12.0] - 2026-09-30

- Judge passage selection and whole-piece progression in existing reviews. An edit needs a concrete reader benefit, not merely shorter or smoother prose; retain clear originals and useful repetition.
- Add conditionally loaded writing-method cases, complete fictional examples, and fix/keep/fidelity regression cases. Examples are not additional source evidence or a new body template.
- Preserve the three TLDR units, weighted visual coverage, source-only scope, version 2 review fields and existing review/retry paths. No new reviewer, field or style-only loop.
- Internal configuration advances from 24 to 26; the repository release version is 0.12.0. Offline and writing-fragment verification does not certify every live host or publishing path.

## [0.10.0] - 2026-09-22

## [0.8.1] - 2026-09-07

## [0.8.0] - 2026-08-27

## [0.5.0] - 2026-08-20

### Added

- Added a mandatory execution-efficiency contract that completes source and review inputs before rendering, keeps multiple briefs in isolated lanes, and reruns deterministic checks by change impact.
- Added a hash-bound review-readiness validator; incomplete or changed source, draft, render, or validation inputs now block independent review packet creation.

### Changed

- Moved full-artifact Blind Reader Replay before the final three-reviewer audit so known comprehension problems are resolved before an expensive audit batch.

## [0.4.0] - 2026-08-20
